# 顧客申請の取込・招待下書き（GAS発信型）設定手順

## 1. 今回の構成と安全上の前提

**既定は `CUSTOMER_APPLICATION_BACKEND=gas`。GASからNexusへ発信する方式です。**

1. 専用GASが非公開のフォーム回答シートを `SpreadsheetApp` で読み、署名付きHTTPS POSTでNexusへ取り込みます。登録は未承認の申請のみです。
2. 固定承認者がNexusで内容を確認して承認すると、管理権限のないカスタマーユーザーが作成され、案内下書きは処理待ちになります。
3. GASが下書きジョブをポーリングし、固定承認者本人のGmailに `GmailApp` で下書きを作成します。メールは人が確認して送信します。

**自動承認・自動送信は行いません。** ToはF列のみ。B列は回答者の記録用で、宛先・CC・BCCには使用しません。フォーム回答自体はメールアドレスの所有証明ではないため、契約内容と招待先を承認前に確認してください。

- **GASのWebアプリデプロイ・GASの一般公開・シートの一般公開は不要です。** `doGet` / `doPost` の公開口も作りません。GASからNexusの専用APIへ発信します。
- **Google CloudでSheets API／Gmail APIを有効化する作業や、Gmailの高度なサービスは不要です。** GAS組み込みサービスを使用します。組織のApps Script利用制限・管理者承認は別途確認してください。
- **`GmailApp` は `https://mail.google.com/` のフルメール権限を要求します。** 読取・作成・送信等を含む広い権限で、下書き専用権限ではありません。本スクリプトは送信しませんが、権限の広さを説明して許可してください。
- 既存のChat・Driveその他のGASプロジェクト、デプロイ、トリガー、秘密は変更しません。**顧客申請専用の別プロジェクト**を作成します。
- 画面の「設定：準備済み」は設定検査の結果であり、接続確認済み・実運用確認済みではありません。実Googleサービス・認証済みAPIの外部疎通は、以下の手順で運用担当者が確認します。

## 2. Djangoの設定とDB適用（運用担当者が実施）

環境変数の名前は [.env.example](../../../.env.example) に空欄で掲載しています。実値は環境別の非公開設定・秘密管理に置き、Git、チャット、ログ、コマンド履歴へ記録しないでください。

| サーバー設定 | 設定内容 |
| --- | --- |
| `CUSTOMER_APPLICATION_BACKEND` | `gas`。旧OAuth方式は後述の任意の互換運用です。 |
| `CUSTOMER_APPLICATION_GAS_SECRET` | 暗号学的乱数で生成した32文字以上（実装上限4,096文字）の共有HMAC秘密。GASの `NEXUS_GAS_SECRET` と同一。環境・固定actorごとに別の秘密を使用します。 |
| `CUSTOMER_APPLICATION_GAS_ACTOR_ID` | 固定承認者の **Djangoユーザーの数値主キー（PK）**。6桁の管理番号／UIDではありません。 |
| `CUSTOMER_APPLICATION_GAS_MAILBOX` | 固定承認者のNexus登録メールと完全一致する社内管理者メール。GASの実効実行ユーザーも同じメールでなければなりません。 |
| `CUSTOMER_APPLICATION_PUBLIC_URL` | GASから到達できる公開HTTPS **originのみ**。例：`https://nexus.example.com`。末尾 `/`、パス、クエリ、フラグメント、ユーザー情報なし。GASの `NEXUS_BASE_URL` と一致させます。招待リンクにも使用します。 |
| `GOOGLE_WORKSPACE_DOMAIN` | 既存の社内ドメイン設定（小文字、`@`なし）を確認します。招待先のドメインへ置き換える設定ではありません。 |

固定actorは**有効なスタッフ1名**とし、その本人が承認・GAS実行・Gmail下書き確認を担当します。他の管理者は閲覧・却下できますが、GAS申請の承認はできません。ボタン非表示／無効化だけに依存せず、サーバーでも制限します。

### 適用順序

1. 稼働DBをバックアップし、既存申請・cursor・下書きID・作成試行記録を保全します。
2. 運用担当者が稼働環境で通常のDjangoマイグレーション適用を行います。新規対象は [0091_customer_application_gas.py](../../../tenasapo_knowledge/migrations/0091_customer_application_gas.py) です。依存する [0089_customer_application.py](../../../tenasapo_knowledge/migrations/0089_customer_application.py)、[0090_customer_application_google.py](../../../tenasapo_knowledge/migrations/0090_customer_application_google.py) が未適用なら併せて適用します。**この手順書・UI変更ではDBへ自動適用しません。**
3. 非公開設定と新コードを反映し、アプリの全workerを再起動します。GASトリガーはまだ作成しません。
4. 下記の専用GASを用意し、署名ping → 手動取込 → 1件の承認・下書き確認の順で検証します。

既存の `GOOGLE_AUTO_CREATE_USER=True` による初回Googleログイン時の自動作成は別機能です。事前承認必須の環境では `False` を検討しますが、社内利用者にも影響するため無断で変更しないでください。

## 3. 専用GASプロジェクトを用意する

1. 固定承認者本人の社内Googleアカウントで、顧客申請専用のApps Scriptプロジェクトを新規作成します。編集権限は秘密・メールアクセス権を扱う管理者に限定します。
2. [customer_application_bridge.gs](../../../scripts/users/customer_application_bridge.gs) の内容をスクリプトへ貼り付けます。既存の別用途GASへ追記しません。
3. プロジェクト設定でマニフェストを表示し、[appsscript.customer_application.json](../../../scripts/users/appsscript.customer_application.json) の**内容を、GAS側の [appsscript.json](../../../scripts/users/appsscript.customer_application.json) として貼り付け**ます。リポジトリ側のファイル名でGASへ追加するのではありません。
4. 「スクリプト プロパティ」に次を登録します。秘密の実値はスクリーンショットや実行ログへ出力しません。

| Script Property | 設定内容 |
| --- | --- |
| `NEXUS_BASE_URL` | `CUSTOMER_APPLICATION_PUBLIC_URL` と同一のHTTPS origin。末尾 `/`・パスなし。 |
| `NEXUS_GAS_SECRET` | サーバーの `CUSTOMER_APPLICATION_GAS_SECRET` と同じ32文字以上の暗号学的乱数の秘密。 |
| `NEXUS_ENVIRONMENT` | Djangoが `DEBUG=False` なら `production`、`DEBUG=True` なら `development`。ホスト名から推測しません。 |
| `NEXUS_GAS_MAILBOX` | `CUSTOMER_APPLICATION_GAS_MAILBOX` と同一の、固定承認者本人の正確なメールアドレス。 |

5. 本人が必要なGAS権限を確認・許可します。マニフェストは外部HTTP通信、シート読取、**フルメール権限**、本人メール取得、明示的なトリガー管理を要求します。全サービスの実動作確認とは別です。

`Session.getEffectiveUser().getEmail()` が空でないことと、設定メールとの完全一致を、取込・下書き処理時に独立して検証します。共有秘密が一致しただけではメールボックス本人確認の代わりになりません。時間主導トリガーも同じ本人が作成してください。

環境ごとにGASプロジェクト・DB・origin・秘密を分離します。ステージングも `DEBUG=False` なら識別値は `production` なので、同じ値を使うことと秘密・DBを共用することを混同しないでください。**作成試行済みの申請はactor・環境・メールボックスを後から切り替えて処理し直せません。**

### 公開関数と実行範囲

| 関数 | 実行内容 |
| --- | --- |
| `testNexusBridge` | 署名付きstatus pingのみ。シート・Gmail・実効ユーザーへアクセスせず、ユーザーやメールを書き込みません。リプレイ防止用nonceの記録は行います。 |
| `syncNexusApplications` | 回答取込のみ。1回最大200行。承認・ユーザー作成・下書き処理はしません。 |
| `processNexusInvitationDrafts` | 下書きジョブのポーリングと処理のみ。1回最大10件。 |
| `runNexusBridge` | 取込と下書き処理を組み合わせて1回実行。 |
| `installNexusBridgeTrigger` | `runNexusBridge` を約5分ごとに実行するトリガーを明示的に作成。**検証完了まで実行しません。** |
| `removeNexusBridgeTrigger` | このプロジェクトの `runNexusBridge` トリガーだけ削除。他用途のトリガーは変更しません。 |

関数の保存やping成功だけではトリガーは作成されません。GASの実行時間・割当・トリガー遅延があるため、即時反映を保証するものではありません。

## 4. 回答シートの権限・形式

| 項目 | 固定値 |
| --- | --- |
| スプレッドシートID | `1JaWW0c_CE9W5_egLvoqrWcnwuIbb6QCERBRrQvAE5Pg` |
| シートID（gid、タブ名ではない） | `1583871824` |

シートの社内共有制限を維持し、固定承認者本人へ閲覧権限を付与します。「リンクを知っている全員」への共有やウェブ公開は不要です。GASの許可だけではシート権限は付きません。

1行目のA～Fは空白も含め次に完全一致させます。回答は2行目以降です。

| 列 | 見出し | 用途 |
| --- | --- | --- |
| A | タイムスタンプ | 申請日時 |
| B | メールアドレス | 回答者の記録のみ。宛先・CC・BCC・ログインIDに不使用 |
| C | 会社名 | 会社との紐付け |
| D | 部署名 | 部署名（空欄可） |
| E | 契約者氏名 | 表示名 |
| F | メールアドレス | ログインID・登録メール、下書きの唯一のTo |

- 回答は**追記専用**です。行の削除・途中挿入・並べ替え・既存回答の上書き・列構成変更は避け、閲覧には原本の行順を変えないフィルタ表示等を使います。
- `getDisplayValues()` で読みます。A列は例：`2026/11/19 09:30:00` または `2026/11/19 09:30`。`2026-11-19 09:30:00` も受け付けます。漢字の独自表示や月／日／年順は使わず、シートとDjangoのタイムゾーン運用を合わせます。
- 1回最大200行を読み、全空行を除外して送信します。保存済みcursorから継続し、`スプレッドシートID:シートID:行番号` の `source_key` で重複登録を防ぎます。cursorや原本の行番号を手動でリセットしないでください。
- 取込は未承認申請の登録だけです。フォーム送信・GAS取込・定期実行で自動承認しません。

## 5. 本番の最初の確認（トリガーなし・1件から）

**localhost、127.0.0.1、社内限定到達先、自己署名証明書ではGASからの確認はできません。** 有効な公開HTTPS証明書とGASから到達できるoriginが必要です。リダイレクトは追跡せず、証明書検証も無効化しません。

ホストへHTTPSで到達して **404が返っただけでは、ホストのHTTPS応答を見ただけ**です。認証済みの実APIルート・共有秘密・DB適用・メールボックスの正常性を証明しません。未署名のブラウザーアクセスも検証の代用になりません。

1. 本番設定・バックアップ後の0091適用・worker再起動を確認します。**定期トリガーはまだ作りません。**
2. 固定承認者が `testNexusBridge` を手動実行し、署名status ping成功を確認します。これはシート権限・Gmail権限・実効メールの検証ではありません。
	- 成功ログは `NEXUS_BRIDGE_OK`。失敗時は `HTTP_STATUS` と固定の `HTTP_ERROR` を確認します。401は署名・環境・時刻、404はURLまたは未配備、503の `invalid_configuration` はサーバー設定・固定ユーザー、`service_unavailable` はDB適用・サーバー側の確認が必要です。`NETWORK_ERROR` はHTTP応答前の通信例外です。
3. `syncNexusApplications` を手動実行します。Nexusの「ユーザー一覧 → 申請一覧」（`/users/applications/`）を開き、「表示を更新」で未承認申請を確認します。初回取込は最大200行なので、ユーザー・下書きの検証対象は承認する1件に絞ります。
4. 固定承認者が検証用の**1件だけ**B列・F列・会社・氏名を確認し、「承認してユーザー作成・下書き待ちにする」を押します。他の管理者では承認できず、閲覧・却下のみ可能なことも確認します。
5. `processNexusInvitationDrafts` を手動実行します。下書き待ちが他にもあると最大10件を処理するため、初回は対象1件だけが待機する状態で行います。
6. 同じメールボックスのGmailで下書き1件、ToがF列のみ、CC／BCCなし、案内本文・パスワード設定リンク・本文末尾の `Nexus連携ID:` を確認します。Nexusでも下書きIDの記録を確認します。**自動送信されていないことを確認**します。
7. 再度処理してもユーザー・下書きが増えないことを確認します。送信は必要性と宛先を確認して人が行います。結果不明・削除・送信済みの扱いは次節に従います。
8. 手動の実疎通・重複防止確認に合格してから、同じ本人が `installNexusBridgeTrigger` を1回実行します。約5分ごとの取込・下書き処理を確認します。停止には `removeNexusBridgeTrigger` を使います。

承認により作成するのは `is_staff=False`、`is_superuser=False`、役割グループなし・分析除外のカスタマーユーザーです。管理番号800001～899999を採番し、会社へ紐付けます。既存ログインID／メールと重複する場合は承認を停止し、既存ユーザーを上書きしません。

GASモードでは一覧にOAuth認可カードや「回答を取込」は表示しません。「表示を更新」はブラウザー表示更新だけです。旧Google接続・取込ルートもGASモードでは無効です。下書き作成待ちを、作成済み・接続確認済みと解釈しないでください。

## 6. 下書きの結果不明・再キューと復旧

承認時点でユーザー作成は確定しますが、下書き作成は非同期です。失敗しても再承認・ユーザー再作成はしません。固定承認者かつ当該申請の承認者本人が、詳細の**下書き処理を再キュー・照合**を使用します。繰り返しても同一申請の処理を重複作成しないための操作であり、GASの即時実行ボタンではありません。次回の定期処理を待つか、GASで `processNexusInvitationDrafts` を手動実行します。

### at-most-onceの作成制約

- `ScriptLock` により同じプロジェクトの取込・下書き処理の重複実行を防ぎます。
- サーバーはclaimで作成許可と永続的な試行記録を確定し、GASは `GmailApp.createDraft` **前に**ローカルのattempted／uncertain記録を永続化します。サーバーの許可とローカル記録を組み合わせ、作成試行済みでは新規作成を許可しません。
- **claim応答を受け取れなかった場合も、未作成と決めつけて再作成しません。** 次の処理は復旧照合だけになることがあります。実際にはGoogleへの作成まで到達していなくても、安全側で停止します。必ず1件できることより、重複作成を避ける設計です。
- `GmailApp` で本文の完全な行マーカー `Nexus連携ID: <固定の識別子>` とTo／空のCC・BCCを照合します。高度なGmail APIやカスタムMessage-IDヘッダーへの依存はありません。本文マーカーを削除・改変しないでください。
- 照合対象は**最大1,000件の下書き**です。1,000件を超える場合、照合不能・複数一致の場合は安全側で停止し、新規作成しません。部分走査で「存在しない」と判定しません。

| 状況 | 対応 |
| --- | --- |
| 処理中 | 5分以上待って表示を更新します。待ち時間経過は再作成許可ではありません。 |
| 作成試行前の設定・権限エラー | 設定を修正して再キュー・処理します。作成許可と未試行条件を満たす場合だけ初回作成できます。 |
| timeout・通信断・ack失敗・claim応答不明 | 同じactor・環境・メールボックスで既存下書きを照合し、見つかればIDを復旧します。作成試行済みなら見つからなくても再作成しません。 |
| 下書きID記録済み | 存在確認による再作成はしません。Gmailで削除・送信済みでも再作成しません。結果不明のまま削除・送信した場合も同様です。 |
| 走査上限・照合不能 | 運用担当者が同じメールボックスと状態を確認します。試行記録を消す回避策は禁止です。 |
| 招待リンクの失効・設定済み | トークンは自動更新・再発行しません。ユーザー一覧から再設定リンクを発行し、内容を確認して手動で案内します。 |

**DBの試行記録・下書きID、GASの `NEXUS_GAS_ATTEMPT_` で始まるプロパティを削除しないでください。** 別プロジェクト・別actor・別環境・別メールボックスへの切替で再作成を試みないでください。GASの記録を失った場合もサーバーの試行記録を消さず、安全側の照合運用を維持します。既存OAuth申請・既存下書き・保存資格情報も削除せず、方式変更だけで自動移行・再作成されるとは考えないでください。

招待リンクは `PASSWORD_RESET_TIMEOUT`（Django既定3日）に従います。パスワード設定画面ではF列のメールを入力し、設定後の同一トークンは再利用できません。

## 7. 署名通信・秘密とログ

GASから次の4本へ **POST** します。GAS側の公開エンドポイントではありません。

| パス | 用途 |
| --- | --- |
| `/api/customer-applications/gas/status/` | 署名ping・設定情報とcursor確認。ユーザー・メールへの書込なし。 |
| `/api/customer-applications/gas/import/` | 回答を未承認申請として取り込み。自動承認なし。 |
| `/api/customer-applications/gas/claim/` | 下書きジョブと作成／照合許可の取得。 |
| `/api/customer-applications/gas/ack/` | 下書きIDまたは結果不明の記録。 |

HMAC-SHA256の署名対象は、バージョン識別子、環境、HTTP method、正確なpath、timestamp、nonce、bodyのSHA-256です。送信ヘッダーは `X-Nexus-Timestamp`、`X-Nexus-Nonce`、`X-Nexus-Signature`。期限・nonce再利用を検査します。環境別・固定actor別の秘密管理とサーバー設定によって実行主体を固定します。プロキシでpathやbodyを書き換えないでください。

応答は別のサーバー署名付きではなく、有効なHTTPS証明書と正しいoriginを信頼します。HTTP化・証明書検証無効化・リダイレクト追跡でエラーを回避しないでください。

共有秘密、署名ヘッダー、リクエスト／レスポンス本文、申請者個人情報、メール本文、パスワード設定URLを、HTTPデバッグログ・APM・エラー収集・チャットへ出力しないでください。秘密はサーバーの管理設定とGAS Script Propertiesだけで管理し、両者の編集権限・DB・バックアップへのアクセスを制限します。

## 8. 旧OAuth方式（任意の互換運用・今回の計画対象外）

既存OAuth方式を明示的に選ぶ場合のみ `CUSTOMER_APPLICATION_BACKEND=oauth` とします。既存レコードを削除せず、GASで作成試行済みの申請をOAuthへ切り替えて再作成しないでください。

OAuth方式では既存ログイン用clientのCloud projectでSheets API／Gmail APIを有効化し、社内限定の同意画面、追加のSheets読取・`gmail.compose`権限、公開originに対する `/users/applications/google/callback/` の登録が必要です。ログイン用の既存URI・Drive設定を削除しません。`gmail.compose`にも送信権限が含まれます。管理者本人が申請一覧の「Googleアクセスを許可」で追加認可してから「回答を取込」を操作する旧運用です。

OAuth callbackの `code`・`state` をアクセスログへ残さない設定と、資格情報の暗号化・環境分離・再認可の運用も必要です。**これらのCloud設定・追加OAuth認可は、今回のGAS方式には不要です。** 既存OAuthの保存データを消して移行する手順ではありません。
