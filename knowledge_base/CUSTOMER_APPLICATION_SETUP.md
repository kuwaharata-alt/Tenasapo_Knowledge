# 顧客申請の取込・招待下書き 設定手順（Google API方式）

## 方式・準備するもの

- 管理者の明示的な追加認可により、Djangoから **Sheets APIで回答を読み、Gmail APIで承認者本人の下書きを作成**します。メール送信APIは実装していません。
- **旧GAS署名通信方式は廃止**です。GASの作成・全員公開、スプレッドシートの公開、HMAC共有秘密、`CUSTOMER_APPLICATION_SECRET`、`CUSTOMER_APPLICATION_GAS_URL`、フォーム送信／定期トリガーはいずれも不要です。
- 既存Googleログイン用OAuth clientを再利用しますが、**ログイン認証と申請管理用API認可は別**です。既存ログインのscopesは変更せず、利用する管理者が申請一覧から追加許可します。Drive連携の保存資格情報も流用しません。
- 必要なのは、既存clientのCloud projectを設定できる担当者、社内Google Workspaceアカウントを持つNexus管理者、対象シートの閲覧権限、公開HTTPS originです。
- **実際のGoogleとの外部疎通は未検証です。** 設定・追加認可を完了してから、末尾の確認を実施してください。DB適用状況は環境ごとに確認してください。開発ワークスペースのSQLiteにはバックアップ後に0090まで適用しています。

## 1. 既存OAuth clientのGoogle Cloud設定

1. **現在Googleログインに使っているOAuth clientのCloud project**を開きます。新しい別clientへの置換は不要です。
   - 実装は、既存の`SOCIALACCOUNT_PROVIDERS['google']['APP']`を優先します。未設定なら現在のSiteに紐付く一意のGoogle `SocialApp`を使用します。両者のclient ID／secretを混在させません。
   - 秘密の実値を手順書・ログ・チャットへ転記しないでください。
2. 「APIとサービス → ライブラリ」で **Google Sheets API** と **Gmail API** を有効にします。既存ログイン・Drive等の設定は削除しません。
3. OAuth同意画面（Google Auth Platform）の対象ユーザーは**社内限定（Internal）を維持**します。外部公開へ切り替える必要はありません。組織のAPIアクセス制御・ポリシーに従い、Workspace管理者の承認が必要な場合があります。
4. 同意画面のデータアクセスに、次の申請管理用scopesを設定・確認します。既存ログイン側のscope要求には追加しません。

   | scope | 用途 |
   | --- | --- |
   | `openid` | Google本人識別 |
   | `email` | 本人の検証済みメールアドレス確認 |
   | `https://www.googleapis.com/auth/spreadsheets.readonly` | 回答シート読取 |
   | `https://www.googleapis.com/auth/gmail.compose` | Gmail下書き作成・照合 |

   **`gmail.compose`には送信権限も含まれます。** 下書きだけに限定した権限ではありません。ただし本機能には送信APIの実装がなく、送信は人がGmailで行います。権限の範囲を管理者へ説明してから許可してください。
5. 同じOAuth clientの「承認済みのリダイレクトURI」に、次を**追加**します。

   `<CUSTOMER_APPLICATION_PUBLIC_URL>/users/applications/google/callback/`

   例：`https://nexus.example.com/users/applications/google/callback/`

   **既存ログイン用リダイレクトURIは維持**し、既存Drive用等のURIも削除・置換しません。末尾の`/`まで完全一致させます。[config/urls.py](config/urls.py) はアプリURLをrootにincludeしており、[アプリのURL定義](tenasapo_knowledge/urls.py) に対して追加のパス接頭辞はありません。

## 2. Django設定・DB適用

| 設定 | 要件 |
| --- | --- |
| `CUSTOMER_APPLICATION_PUBLIC_URL` | 例：`https://nexus.example.com`。**HTTPSのoriginのみ、末尾`/`不可**。パス・クエリ・フラグメント・ユーザー情報を付けない。OAuth callbackと招待URLの基準です。 |
| `GOOGLE_WORKSPACE_DOMAIN` | 既存の社内ドメイン設定を使用。小文字のドメイン名（`@`なし）を確認します。別の招待先ドメインへ変更する設定ではありません。 |
| 既存Google OAuth client設定 | 既存ログイン用のclient ID／secretをそのまま利用。申請専用の追加client secretやHMAC秘密は不要です。 |

環境変数等は稼働環境の既存の秘密管理方法で設定し、実値をソース管理やコマンド履歴へ残さないでください。

### 適用順序（運用担当者が実施）

1. **稼働DBをバックアップ**します。既存申請・取込cursor・下書き作成記録も保全します。
2. 稼働環境のPython・Django設定で、通常のDjangoマイグレーション適用（`migrate`）を実施します。追加済みの[0090_customer_application_google.py](tenasapo_knowledge/migrations/0090_customer_application_google.py) が対象です。依存する[0089_customer_application.py](tenasapo_knowledge/migrations/0089_customer_application.py) が未適用なら併せて適用されます。
3. 設定と新コードを反映して**アプリの全workerを再起動**します。
4. 次節の権限確認後、申請一覧から管理者本人が追加認可します。

**自動ユーザー作成との関係：** 既存の`GOOGLE_AUTO_CREATE_USER=True`によるGoogle初回ログイン時の自動作成は、申請承認とは別機能です。必ず事前承認制にする環境では`False`を検討してください。既存の社内ユーザー自動作成にも影響するため、運用確認なしに変更しないでください。

## 3. 回答シートの権限・形式

取込先はコードで固定されており、画面やリクエストから別のシートへ変更できません。

| 項目 | 固定値 |
| --- | --- |
| スプレッドシートID | `1JaWW0c_CE9W5_egLvoqrWcnwuIbb6QCERBRrQvAE5Pg` |
| シートID（URLのgid。タブ名ではない） | `1583871824` |

**シートの社内共有制限を継続**し、取込を行う管理者本人のGoogleアカウントに閲覧権限を付けます。「リンクを知っている全員」への共有や「ウェブに公開」は不要です。OAuth認可だけではシートの閲覧権限は付きません。

1行目のA～Fは、空白も含め次の見出しに完全一致させます。回答は2行目以降です。

| 列 | 見出し | 用途 |
| --- | --- | --- |
| A | タイムスタンプ | 申請日時 |
| B | メールアドレス | 回答者の記録のみ。ログインID・宛先・CCには不使用 |
| C | 会社名 | 会社との紐付け |
| D | 部署名 | 部署名（空欄可） |
| E | 契約者氏名 | 表示名 |
| F | メールアドレス | 作成ユーザーのログインID・登録メール、下書きのTo |

- **回答は追記専用です。行の削除・途中挿入・並べ替えは禁止**し、既存回答の上書きも避けます。列位置・見出しは変えず、閲覧にはフィルタ表示等を使って原本の行順を維持します。
- Sheets APIの標準的な表示値`FORMATTED_VALUE`で読みます。A列は日本の年／月／日順の標準表示、例：`2026/11/19 09:30:00`または`2026/11/19 09:30`にします。`2026-11-19 09:30:00`形式も受け付けますが、年月日を漢字で表す独自表示や月／日／年順は使わないでください。シートとDjangoの日時・タイムゾーン運用を合わせます。
- 1回の「回答を取込」で**200行×最大10ページ（最大2,000行）**を読みます。全空行は除外されます。各ページの申請と次回開始行（cursor）を同じDBトランザクションで永続化します。
- 上限到達・途中失敗時は保存済みcursorから次回再開します。末尾到達後も全件再走査せず追記を取得します。`スプレッドシートID:シートID:行番号`を`source_key`として重複登録を防ぐため、行移動やcursorの手動リセットはしないでください。

## 4. 管理者の操作

1. Nexusの**ユーザー一覧 → 申請一覧**を開きます（`/users/applications/`。Django標準管理画面ではありません）。有効なスタッフまたはスーパーユーザーで操作します。デモ／CSの表示モードからはAPI連携できません。
2. **Googleアクセスを許可**を押し、Nexusに登録されている本人と同じ社内Googleアカウントで追加認可します。既存のGoogleログインだけではAPI認可は完了しません。
   - Googleの`email_verified=True`、`hd`と`GOOGLE_WORKSPACE_DOMAIN`の一致、GoogleメールとNexusの`user.email`の一致を確認します。
   - ID tokenの署名・audience・nonceとUserInfoの`sub`を検証し、既存のGoogle `SocialAccount`があればその`uid`とも照合します。**別メール・別Googleアカウントでの代理認可は不可**です。
3. **回答を取込**を押します。フォーム送信だけでは取込・承認・ユーザー作成は実行されません。
4. **内容を確認**でB列の回答者・会社・氏名・F列の招待先を確認し、**承認してユーザー・下書きを作成**を押します。却下ではユーザー作成・メール通知は行いません。
5. **承認者本人のGmail下書き**を開き、To・本文・招待リンクを確認して、必要に応じて人が送信します。ToはF列のみ、CC／BCCは付けません。

承認で作成するのは**管理権限なしのカスタマーユーザー**です（`is_staff=False`、`is_superuser=False`、役割グループなし、分析除外）。管理番号800001～899999を採番して会社に紐付けます。F列が既存ログインID・登録メール等と一致する場合は承認を停止し、既存ユーザーを上書きしません。申請UUIDと承認状態、承認済みメールの制約等で重複作成を防止します。

**フォーム回答はメールアドレスの所有証明ではありません。** 契約内容と招待先を管理者が確認してから承認・送信してください。

## 5. 下書きの失敗・結果不明時

**下書きが失敗しても、承認とユーザー作成は確定済みです。** 再承認やユーザーの再作成ではなく、承認者本人が申請詳細の**下書き作成を再試行**を使います。他の管理者のメールボックスへ切り替えて復旧することはできません。

| 状況 | 対応・実装上の制約 |
| --- | --- |
| 作成中 | 作成権のleaseは5分です。5分以上待って状態を確認します。期限経過は「再POSTしてよい」という意味ではありません。 |
| Googleへの作成試行前の失敗 | 設定・認可を直して再試行します。まだ永続的な試行記録がなければ、下書き照合後に初回作成できます。 |
| timeout・通信断などで作成結果が不明 | **作成POSTの再送は禁止**です。再試行は同じメールボックスのMessage-ID照合だけを行い、見つかれば既存下書きIDを復旧します。見つからなくても新規作成しません。 |
| 照合エラー・走査上限 | 下書き走査は100件×最大10ページ、**最大1,000件**です。走査を完了できなければ停止します。件数やGmailの状態を手動確認し、作成記録を消して回避しないでください。 |
| 下書きIDが保存済み | 存在確認や再作成はしません。Gmailで削除・送信済みでも再作成しません。結果不明のまま削除・送信した場合も、照合できないことを理由に新規POSTしません。 |
| 招待リンクの失効 | 自動再発行しません。ユーザー一覧から再設定リンクを発行し、既存下書きのリンクを手動で置き換えるなど、確認のうえ案内します。 |

重複防止のため、**作成POSTより前に**`draft_remote_attempted`、固定の`draft_message_id`、`draft_google_sub`、`draft_mailbox_email`をDBへ永続保存します。成功応答を保存できなかった場合も、同じ承認者・Google sub・メールの下書きをMessage-IDで照合します。申請UUIDは本文末尾にも付加しますが、復旧照合は本文検索ではありません。古いworkerの結果が新しい処理状態を上書きしないよう試行IDも照合します。

**これらの記録や`draft_id`を手動で消さないでください。** 安全側で停止するため、Googleへ実際には到達しなかった場合も、試行記録があれば再POSTしないことがあります。復旧には承認者本人の同一メールボックスへの再連携が必要です。

招待リンクの有効期限は`PASSWORD_RESET_TIMEOUT`（Django既定3日）に従います。失効した保持トークンは再試行でも更新しません。パスワード設定画面ではF列のメールアドレスを入力し、設定後は同じトークンを再利用できません。

## 6. 資格情報・環境分離・連携解除

- refresh tokenは、`SECRET_KEY`からHKDFで導出した鍵によるFernet暗号化でDB保存します。申請連携専用contextを使い、Driveと分離しています。暗号化データは**actor／environment／client ID／Google sub／email**にbindされ、別ユーザー・環境への単純コピーでは利用できません。access tokenは都度取得し、永続保存しません。
- 環境判定は既存の`current_chat_environment()`に従い、**`DEBUG=True`なら`development`、`False`なら`production`**です。接続は管理者×環境で分離します。ホスト名や独自環境変数による判定ではありません。ステージングも`DEBUG=False`なら`production`扱いなので、環境別DB・公開origin・認可運用で分離してください。申請・取込cursor自体を環境別にする仕組みではありません。
- 認可はstate・PKCE・nonceと管理者セッション等を照合し、有効期限は10分です。**stateの消費ハッシュはDBに保存し、全worker共通で再利用を拒否**します。state再利用防止専用の共有キャッシュ追加は不要です。通常のDjangoセッションが全workerで利用できる構成は維持します。
- **`SECRET_KEY`をローテーションしたら各管理者が再認可**してください。旧鍵へのフォールバックはありません。clientや本人情報の変更時も再連携が必要です。申請・下書きの永続作成記録は削除しません。
- 申請一覧の**連携解除**は、本人の**現在環境のローカル接続だけ**を削除します。既存ログイン・Drive接続を削除せず、Google側へのtoken取消APIも呼びません。
- Google側の許可も取り消す場合はGoogleアカウントの接続アプリ管理で行います。**同じOAuth clientへの取消は、既存GoogleログインやDrive連携にも影響しうる**ため、関係者と確認してください。

## 7. 旧専用GASの停止・ログ対策・稼働確認

### 旧GASを配置済みの場合

- **今回の顧客申請専用GASだけ**停止／デプロイをアーカイブし、専用トリガーがあれば停止します。新方式へ旧署名通信を併用しません。
- 旧専用設定`CUSTOMER_APPLICATION_GAS_URL`・`CUSTOMER_APPLICATION_SECRET`や専用ScriptPropertiesは不要です。下書き等の既存記録は移行確認まで保全し、旧GASで作成済みの下書きは手動確認します。旧GAS側だけにある記録・本文マーカーを新方式が自動移行・照合するわけではありません。
- **既存Chat用GAS・そのデプロイ・トリガー・秘密・環境変数は変更しません。** 旧顧客申請専用GASのソースは今回削除済みですが、Google側に配置したデプロイは管理者が停止してください。

### ログ・秘密保護

- **追加OAuth callbackの`code`・`state`をアクセスログ等へ残さない**よう、認可開始前にリバースプロキシ・Webサーバー・クラウドのアクセスログ／APMで当該callbackのクエリ文字列を除外・マスクします。アプリ側の例外秘匿だけではURLログを防げません。
- `access_token`・refresh token・client secret・Authorizationヘッダー・認可URL／応答・申請者の個人情報・メール本文・パスワード設定URLを、HTTPデバッグログ・エラー収集・スクリーンショット等に出さないでください。DBとバックアップへのアクセスも制限します。

### 追加認可後の確認チェックリスト

- [ ] 社内限定のまま本人が追加認可でき、既存ログイン／Drive設定が維持されている。
- [ ] 別メール・別ドメイン・権限のない利用者ではAPI連携できない。
- [ ] 非公開シートを管理者の閲覧権限で取り込める。6列見出し、日時表示、200行超、空行、途中失敗後のcursor継続を確認した。
- [ ] 承認で権限なしのカスタマーが1件だけ作成され、F列のみをToとする下書きが承認者本人のGmailにできる。自動送信やCC／BCCがない。
- [ ] 結果不明時の同一Message-ID照合、再POST禁止、走査上限、削除／送信後の再作成なしを安全な検証環境で確認した。
- [ ] 期限切れリンクの手動対応、再認可、ローカル連携解除、callbackのクエリログ除外を確認した。

外部通信を置換したテストだけでは、実Googleの認可・組織ポリシー・Sheets／Gmailの疎通は保証できません。**DB適用と追加認可後の実環境確認が完了するまで、本番運用を開始しないでください。**
